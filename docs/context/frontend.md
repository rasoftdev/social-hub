# Frontend

`src/renderer/styles.css` defines the dark theme. `index.html` holds the shell and forms. `renderer.js` creates cards, lists and menus with Lucide glyphs and service SVGs from `icons.js`.

- **Type and layout.** Base 13px Segoe UI Variable → Segoe UI → system-ui → sans-serif. Page titles 26px/600, hero `clamp(36px, 5vw, 56px)`/800 with 1.08 line height, hero subtitle 17px/1.55, section labels 11px/600 uppercase. The title bar is 36px high. Window defaults to 1280×800, minimum 800×500. Scrollable content uses `.page` padding 32px 40px 80px and max width 1100px.
- **Collapsible sidebar.** The sidebar is 220px wide when expanded and 72px when collapsed. `#sidebar-toggle` sets `aria-expanded` to `true` when expanded and `false` when collapsed. Its `aria-label` and `title` use `sidebar.collapse` when expanded and `sidebar.expand` when collapsed. It has a cyan focus outline. The collapsed sidebar hides the wordmark, navigation labels, section headings, account metadata, account menu buttons, global mute button and add-account text. `#content` and `.wave` follow the sidebar width, and the main process updates the horizontal position and width of each `WebContentsView`. The preference is saved in `localStorage` under `sidebar-collapsed` and restored on startup.
- The sidebar toggle uses a 30px square button with zero padding and a centered 16px SVG chevron that rotates when collapsed.
- The expanded wordmark stays on one line at 17px with an 8px brand gap to fit the compact 220px sidebar.
- **Embedded service views.** The `#accounts` sidebar and `#content` host retain the dark app palette. Embedded sites are asked for a dark color scheme; background CSS is scoped to the service origin. WhatsApp uses a gradient splash screen. Preserve the app CSS `forced-colors` rules. The `#accounts` drag region is offset 8px into the panel padding; its 2px indicator is visible while hovering the list or when focus is inside. The account list has a 20px bottom margin before the Add account button in both expanded and collapsed sidebar states.
- **Navigation and cards.** Work with `.nav-item`, `.acc`, `.card` and `.panel-block`. Nav and sidebar rows use 12px radii, hover fill and an active state. Cards use 16px radii, 20px padding and a full 1px outline. Service cards brighten on hover with `0 10px 28px rgba(30, 111, 242, .25)`. Home grids auto-fill at minimum 190px/16px gap for services and 240px/12px gap for account details. Status uses dots, mute glyphs and red unread badges (11px/600, 16px line height). Add actions use a dashed outline. Keep full outlines and avoid decorative side borders.
- **Settings and menus.** Settings use flex rows with 12px vertical padding and a divider. Checkboxes render as 42×24px switches with a blue gradient when checked and a cyan focus ring. The language radiogroup uses segmented buttons with `aria-checked`, arrow keys and cyan focus outlines. Card popovers and context menus use panel fill, 12px radius and `0 12px 30px rgba(0, 0, 0, .5)`. Account menu options have a 4px gap, and a single highlight follows the pointer or keyboard focus. The context menu supports keyboard navigation, visible focus and `aria-disabled` at .4 opacity.
- Right-clicking an account in the collapsed sidebar opens the same styled account menu used by the expanded sidebar over the open service, while keeping the sidebar at 72px.
- **Forms and dialogs.** Modal overlays start under the title bar. Dialogs are 480px wide, capped at viewport minus 32px, with `0 20px 60px rgba(0, 0, 0, .6)` shadow. Text inputs use 9px 12px padding, 10px radius and cyan focus. Use 12px muted labels and localized placeholders. Account names are optional and capped at 50 characters. Inline errors use `#FF7A7A` at 12px. The service picker uses three columns on desktop, switching at 520px to auto-fit columns with 72px minimum. Cyan outlines the selected service. Actions use 8px 18px padding, 10px radius and hover brightness, with blue-gradient primary, card-hover secondary and danger red variants.
- **Accessibility and states.** Keep localized accessible labels and hide decorative glyphs from assistive tech. The name field receives focus on open and Escape closes its form.
